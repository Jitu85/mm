1. EXECUTIVE SUMMARY & ROOT CAUSE ANALYSIS
-------------------------------------------------------------------------------
The 404 Error encountered at https://jitu85.github.io/virtual/ occurred due to
the following fundamental discrepancies between Next.js defaults and GitHub Pages:

1. Missing Static Export & Base Path Configuration:
   - Next.js by default creates a dynamic Node.js server application.
   - GitHub Pages is a static web host that serves content under the subdirectory
     path '/virtual/'.
   - Without `output: 'export'`, `next build` does not generate static HTML files.
   - Without `basePath: '/virtual'`, all script, CSS, and internal navigation
     links were looking for root domain assets (`/`) instead of `/virtual/`.

2. Node.js API Route Handlers (/api/...):
   - Components were attempting runtime `fetch()` calls to server endpoints like
     `/api/grammar`, `/api/cbse`, and `/api/qa`.
   - GitHub Pages cannot execute Node.js backend server code or API routes.

3. Lack of Static Parameter Generators for Dynamic Routes:
   - Dynamic pages (`/grammar/[volumeNum]/[chapterNum]` and `/module/[id]`)
     did not specify `generateStaticParams()`. Static export requires pre-defining
     all dynamic route parameter combinations so Next.js can generate HTML pages
     during build.

4. Missing Deployment Workflow & `.nojekyll`:
   - No GitHub Actions workflow was configured to build the app on push.
   - GitHub Pages uses Jekyll by default, which ignores folders starting with an
     underscore (such as Next.js asset directory `_next/`). A `.nojekyll` file was
     required in the output directory.

3. DETAILED TECHNICAL RATIONALE BY FILE
-------------------------------------------------------------------------------

• next.config.ts
  - Added `output: "export"`: Forces `next build` to emit a standalone static HTML export in `out/`.
  - Added `basePath: "/virtual"`: Prefixes all routes and assets with `/virtual/` for GitHub Pages URL.
  - Added `images: { unoptimized: true }`: Enables static HTML rendering of image components.

• .github/workflows/deploy.yml
  - Automatically triggers on every push to the `main` branch.
  - Installs dependencies (`npm ci`), runs `npm run build`, creates `./out/.nojekyll`, and publishes
    the `out/` static folder to GitHub Pages using `actions/deploy-pages@v4`.

• src/lib/grammar-data.ts & src/lib/qa-data.ts
  - Previously used Node's `fs.readFileSync(path.join(process.cwd(), ...))` which fails in browser JS.
  - Updated to import JSON data files directly (`import vol1Data from "..."`, `import qaData from "..."`).
  - Allows all data queries (`getVolumes()`, `getChapter()`, `getQASubjects()`, `getFilteredQAItems()`)
    to execute synchronously in both browser client components and SSG build steps.

• src/app/grammar/[volumeNum]/[chapterNum]/ (page.tsx & ChapterClient.tsx)
  - Next.js requires `generateStaticParams()` to be exported from Server Components (without `"use client"`).
  - Split the route: `page.tsx` is a Server Component exporting `generateStaticParams()` for all 28 extracted
    chapters across Vol I, II, and III. It passes params to `ChapterClient.tsx` which handles UI state,
    input fields, and answer verification logic.

• src/app/module/[id]/ (page.tsx & ModuleClient.tsx)
  - Split the route: `page.tsx` exports `generateStaticParams()` returning `[{ id: 'b' }, { id: 'c' }, { id: 'B' }, { id: 'C' }]`.
  - `ModuleClient.tsx` handles interactive Q&A state, subject filters, and test engines.

• src/components/cbse/CBSEModuleHub.tsx & CBSEExamEngine.tsx
  - Changed runtime `fetch('/api/cbse?...')` calls to direct imports from `@/lib/module-c-data`.
  - Eliminates network delay and enables instant offline/static question drill loading.

• Deletion of src/app/api/
  - API routes in Next.js cannot run on static web hosts like GitHub Pages.
  - Deleting `src/app/api` prevents Next.js compiler errors during static export page collection.
